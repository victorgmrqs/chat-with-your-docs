# Testing guide — cwyd-frontend

## 0. Purpose

This guide helps you decide **what to test**, at **which layer** and **how to set up tests**
for each artifact type in `frontend/`: components, server-state hooks, the typed API client,
browser flows and the types that arrive later (streaming chat, upload form, shadcn
compositions). When working on one type, read its file in `artifacts/`. Mock strategies, file
conventions and gotchas are in `references/`.

## 1. Testability Foundations

- **The network is the boundary.** Components and hooks talk to the backend only through the
  typed client on the relative `/api` path. MSW intercepts those requests in Vitest, so tests
  exercise the real client, the real hooks and the real components; only the server is fake.
  Mocking the client module or `fetch` would skip the request building and response parsing
  that break most often.
- **Assert what the user perceives.** Testing Library queries by role and accessible name; the
  same queries double as an accessibility check (labels, headings, `aria-live` regions for
  streaming answers and indexing status). If a query by role cannot find an element, the UI is
  probably not accessible.
- **React 19 renders asynchronously.** State updates after a request or a suspended `use()`
  resolve after the first render: wait with `await screen.findBy*` (wrapped in `act` by RTL 16),
  never with `getBy*` right after an interaction that triggers a fetch.
- **Vitest runs with `globals: false`.** Every test imports `describe/it/expect/vi` from
  `vitest`, and `src/test/setup.ts` registers `cleanup()` explicitly; without it the DOM leaks
  between tests. Vitest 5 clears mock calls before each test by default (`clearMocks`) and fails
  tests with unawaited async assertions.
- **MSW 3 is the contract stand-in.** Handlers live next to the feature, imported from
  `msw/http` (and `msw/sse` for streaming), served by `setupServer` from `msw/node` with
  `onUnhandledFrame: 'error'`, so a request without a handler fails the test instead of hitting
  the network. Response bodies are typed from the OpenAPI schema (CWYD-5) so a contract change
  breaks compilation of the handlers.
- **Polling and streaming need controlled time.** Indexing status is polled; use fake timers
  with `userEvent.setup({ advanceTimers: vi.advanceTimersByTime })`, otherwise user-event hangs.
- **Real browser flows run on the real stack.** Playwright drives the Docker Compose stack
  (nginx → FastAPI → Postgres) for the few journeys that must work end to end; it is the only
  layer that proves the nginx `/api` proxy and the built bundle.

## 2. Testing Criteria

**Worth testing**
- Components with states: loading, empty, error, success (document list, upload, chat),
  including "not enough evidence" answers and failed indexing.
- User interactions with consequences: upload a file, ask a question, retry after a failure,
  delete a document.
- Citations: rendered from the API `sources`, each linked to its document/chunk; never parsed
  from answer text.
- Server-state hooks with logic: polling that stops at a terminal status, error mapping, cache
  invalidation after mutations.
- Client-side validation that protects the backend (file type and size before upload).
- Accessibility contracts: labelled inputs, `aria-live` on streaming/status regions.

**NOT worth testing**
- Static markup and styling (classes, tokens, layout); the design review covers them.
- shadcn/ui primitives themselves (Radix behavior).
- Props passed straight through to a child.
- Full-component snapshots.
- Vite configuration, routing library internals.

## 5. Anti-patterns — Do NOT Do This

- ❌ **Mock the API client module or stub `fetch`** (`vi.mock('../api')`,
  `vi.stubGlobal('fetch')`) — use MSW handlers (see `references/mock-health-rules.md`).
- ❌ **Query by class, test id or text fragments when a role exists** — use `getByRole` with
  the accessible name (see `artifacts/components.md`).
- ❌ **Use `getBy*` right after an action that fetches** — use `await findBy*`
  (see `references/gotchas.md`).
- ❌ **Snapshot whole components** — assert visible behavior (§2).
- ❌ **Test shadcn/ui primitives or Radix internals** — test your composition's behavior
  (see `artifacts/future-types.md`).
- ❌ **Leave `onUnhandledFrame` at its default** — unhandled requests must fail the test
  (see `references/external-systems.md`).
- ❌ **Use real timers for polling tests or `shouldAdvanceTime`** — use fake timers driven
  explicitly (see `artifacts/server-state-hooks.md`).
- ❌ **Cover every component state in Playwright** — E2E proves a few journeys on the real
  stack; states belong to component tests (see `artifacts/e2e-flows.md`).
- ❌ **Parse citations out of the answer text in tests or code** — use the API `sources` (§2).

## 6. E2E Terminology Note

In this guide "component tests" run in Vitest with jsdom and MSW (no browser, no backend).
"E2E" means Playwright driving a real browser against the Docker Compose stack. The backend
guide's "HTTP tests" (FastAPI `TestClient`) are a different layer owned by
`testing-guide-cwyd-backend`.
