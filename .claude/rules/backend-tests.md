# Backend tests

- pytest + pytest-asyncio. Layout: `tests/unit/` (domain and use cases, fakes only, no I/O) and
  `tests/integration/` (adapters and API against real PostgreSQL + pgvector from Docker Compose).
- Never SQLite, never an in-memory database substitute, never mock the database.
- LLM and embeddings use declared fakes that implement the ports (`FakeChatModel`,
  `FakeEmbeddings` with deterministic vectors). No network calls in the test suite.
- At most 3 mocks per test; prefer fakes over mocks. Mock only boundaries (providers, clock,
  external HTTP).
- One behavior per test, Arrange / Act / Assert, name `test_<unit>_<scenario>`. Every use case
  has a success test plus one test per error row it covers.
- Fixture documents live in `backend/tests/fixtures/documents/` and are generated by a script;
  assertions use their known facts (for example the expense limit), not snapshot text.
- Isolation: each integration test runs in a transaction rolled back at teardown, or uses a
  unique `owner_id`.
- Assert behavior and contracts (status codes, error codes, cited chunk IDs, refusal), not
  private implementation details.
