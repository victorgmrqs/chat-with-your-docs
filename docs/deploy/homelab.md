# Homelab deploy (homolog)

The app runs on the author's K3s homelab through GitOps: Argo CD syncs the `homelab-gitops`
repository, and its `development` branch is the **homolog** environment. Production is not
deployed: it needs authentication first ([CWYD-22](https://goncalvesmarques.atlassian.net/browse/CWYD-22)).

| | |
|---|---|
| URL | `https://cwyd-homolog.lab.goncalvesmarques.com` (LAN and tailnet only, never public) |
| TLS | wildcard Let's Encrypt certificate served by ingress-nginx; HSTS from the controller |
| Manifests | `homelab-gitops`: `base/cwyd/` and `overlays/homolog/cwyd/` |
| Argo CD Application | `homelab-homolog` (branch `development`, path `overlays/homolog`, auto-sync with prune and self-heal) |
| Namespace | `homolog` |
| Images | `ghcr.io/victorgmrqs/chat-with-your-docs/{backend,frontend}:sha-<7>`, the tags CI publishes ([CI and images](../../README.md#ci-and-images)) |

## Topology

```text
browser ──HTTPS──> ingress-nginx ──> cwyd-frontend (nginx :8080, SPA + /api proxy)
                                          └──> cwyd-backend (FastAPI :8000) ──> cwyd-db (pgvector pg17, 2Gi PVC)
```

- Only the frontend has an Ingress. NetworkPolicies admit ingress-nginx → frontend → backend → db
  and nothing else, so every API call goes through the frontend nginx (security headers, rate limits).
- The database is the app's own `pgvector/pgvector` StatefulSet: the shared homolog PostgreSQL has no
  pgvector. The backend applies the Alembic migrations on start.
- The ingress raises the body limit to 11 MB (`proxy-body-size`), the same as the frontend nginx.
- Configuration is `overlays/homolog/cwyd/configmap.yaml` (same keys as `.env.example`). Secrets
  (`DATABASE_URL`, `POSTGRES_PASSWORD`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) are a SealedSecret
  generated by `scripts/seal-cwyd-secrets.sh` in `homelab-gitops`.
- Traces go to the cluster's Alloy (`OTEL_TRACES_EXPORTER=otlp`); `CAPTURE_CONTENT` stays `false`.

**Known limitation: shared rate limit.** The frontend nginx keys its limits on the client address,
which behind the ingress is the ingress pod. All clients share one bucket (10 questions and 6 uploads
per minute in total). Acceptable for a private single-user demo; a shared environment needs
`set_real_ip_from` for the ingress CIDR, or the limits moved to the ingress.

## Deploy or update

1. Pick the app commit: a push to `development` whose CI run is green publishes
   `sha-<7>` for both images.
2. In `homelab-gitops`, branch from `development` and set both `newTag` values in
   `overlays/homolog/cwyd/kustomization.yaml`.
3. First deploy only: seal the secret for the namespace (`kubectl` must point at the cluster):

   ```bash
   homelab-infra/scripts/bws-run scripts/seal-cwyd-secrets.sh homolog   # or run it and type the keys
   ```

   `POSTGRES_PASSWORD` only applies when the volume is empty; resealing with a new password needs
   `ALTER ROLE` in the database too.
4. Validate and open a PR against `development`; the `gate` check must pass:

   ```bash
   kubectl kustomize overlays/homolog > /dev/null
   ```

5. Merge. Argo CD syncs homolog within its polling interval (or *Refresh* in the UI).

The backend's `wait-db` initContainer holds it until the database answers `pg_isready`, so on a
fresh volume the pod stays in `Init` while initdb runs instead of crash-restarting. A backend that
restarts anyway is a real failure (`kubectl -n homolog logs deploy/cwyd-backend --previous`).

## Verify

```bash
kubectl -n argocd get application homelab-homolog        # Synced / Healthy
kubectl -n homolog get pods -l 'app in (cwyd-db,cwyd-backend,cwyd-frontend)'
kubectl -n homolog get pods -l app=cwyd-backend \
  -o jsonpath='{.items[0].status.containerStatuses[0].imageID}{"\n"}'   # digest in use
curl -sI https://cwyd-homolog.lab.goncalvesmarques.com | grep -iE '^HTTP|strict-transport'
scripts/smoke.sh https://cwyd-homolog.lab.goncalvesmarques.com          # from this repo
```

The smoke test ends with `SMOKE OK`; what it checks is in the script header. Homelab-only
requests (readiness, HSTS) are in [`docs/http/homelab.http`](../http/homelab.http).

## Rollback

Everything the cluster runs is in `homelab-gitops`, so a rollback is a revert there:

- **Bad image:** `git revert <bump commit>` on a branch from `development`, PR, merge. The previous
  `sha-<7>` comes back; it must still exist in GHCR (images are never deleted while an overlay
  references them).
- **Remove the app:** revert the commit that added `cwyd`. Argo CD prunes the Deployments, Services,
  Ingress and policies. The PVC from the StatefulSet's `volumeClaimTemplates` is **not** pruned; delete
  it by hand (`kubectl -n homolog delete pvc data-cwyd-db-0`) only if the documents can go.
- **Check before merging:** render the target and compare with what runs:

  ```bash
  git diff development..<revert-branch> -- overlays/homolog/cwyd
  kubectl kustomize overlays/homolog | grep 'chat-with-your-docs'
  ```

Database schema changes are forward-only (Alembic): rolling the backend back across a migration is
safe only if the older code tolerates the newer schema. So far every migration has been additive.
